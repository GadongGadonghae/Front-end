# 화면 목적 정의 — UI 개편 3단계 (초안)

> 06 문서 7장 3단계 산출물. 피드백 5(목적과 화면 구성이 안 맞음)·6(값 표현이 맞는지)에 답한다.
> 화면마다 **목적 한 줄 → 주인공 칸 → 사용자가 판단할 질문 → 그 판단에 맞는 값 표현**을 정한다. 1차 배치안(D-99)은 이 문서를 기준으로 만든다.
> 표시: **[제안]** = 사용자 확인 전. 기존 항목·이벤트(화면정의서)는 빼지 않고, 크기·위치·묶음만 바꾼다.

## 0. 시스템 목적 (기능명세서 1.2, PRD 1·2장)

사용자 = **공정 관리자**. 사무실 PC에서 하루 종일 띄워 두고, 현장에 가지 않고 아래 세 가지를 판단한다.

1. **지금 손쓸 곳이 있나?** 어디가 멈췄고 왜 멈췄나 (AS-IS 01·02)
2. **오늘 목표대로 가고 있나?** 뒤처졌다면 얼마나, 어디 때문에 (AS-IS 03)
3. **고장이면 계획을 어떻게 바꾸나?** 재배정 보고서 (AS-IS 04)

나머지(가동률 손실 분석, 예지보전, 품질, 이력)는 이 셋을 뒷받침하거나 지난 일을 돌아보는 용도다. 그래서 **실시간 화면(001·010·002-x)은 1·2번 질문이 주인공**이고, 조회 화면(003·006·007·011)은 돌아보기가 주인공이다.

화면 계층(D-97): 공장(001) > 라인(010) > 공정(002-x) > 설비(002-x 안 선택). 위 계층일수록 "어디"를, 아래 계층일수록 "왜"를 답한다.

| 계층 | 화면 | 답하는 질문 |
|---|---|---|
| 공장 | SCR-001 | 어디에 문제가 있나, 공장 전체로 목표대로 가나 |
| 라인 | SCR-010 | 이 라인의 어느 공정이 막혔나, 라인 계획에서 얼마나 뒤처졌나 |
| 공정·설비 | SCR-002-x | 이 설비가 왜 멈췄나 / 멈출 것 같나 |

## 1. 대표 화면 3개 (시안 대상, D-98)

### 1.1 SCR-001 대시보드

**목적 한 줄 [제안]**: 지금 공장에 손쓸 곳이 있는지, 오늘 목표대로 가고 있는지 2초 안에 안다.

**주인공 [제안]**: 공장 배치도. 화면에서 가장 크고, 고장(D) 설비가 깜빡이며, 그 옆에 "조치 요청"이 있다.

| 판단 질문 | 지금 표현 | 문제 | 바꿀 표현 [제안] |
|---|---|---|---|
| 지금 멈춘 곳이 있나, 어디인가 | 배치도 칸 색·코드 + 오른쪽 세로 열 전체 알림 목록 | 알림 열이 배치도와 같은 무게로 시선을 나눔 (피드백 3) | 배치도 칸 깜빡임(고장만) + **진행 중 고장 건만** 배치도 가까이 작게. 해제·대기·정지 건은 개수와 "알람 이력" 링크로 줄임. D-46 변경 |
| 왜 멈췄나 | 알림 목록 문구 | - | 고장 건 옆에 사유 한 줄 + 지속시간 (데이터 있음) |
| 오늘 목표대로 가나 | 실적(큰 숫자) · 목표 · 달성률 + 00~24시 누적선 vs 목표선 | **달성률이 하루 목표 대비라 낮 동안 항상 낮아 보임** (10시면 순조로워도 약 40%). "괜찮은가"를 바로 못 읽음 | 핵심 숫자 = **지금 기준 차이 "목표보다 N개 앞섬/뒤처짐"**(목표선의 지금 값 − 실적). 그 아래 달성률·목표. 그래프는 누적선 + 시간당 막대(어느 시간에 빠졌나) (D-98, Q-31) |
| 설비가 제 성능을 내나 | OEE 큰 숫자 + 3요소 막대 | **기준값이 없어 숫자가 좋은지 나쁜지 판단 불가** | Q-33 답에 따라. 기준이 없으면 OEE는 보통 숫자로 낮추고 3요소 중 가장 낮은 것을 표시 |
| 불량이 어디서 나나 | 출고 불량률 큰 숫자 + 공정별 불량 수 | 불량률도 기준값이 없음 | 공정별 불량 수가 주인공, 불량률은 보조 (Q-33) |
| 고장 날 것 같은 설비가 있나 | 배치도 노랑·빨강 테두리 + 알림 목록에 섞임 | 고장 알림과 섞여 헷갈림 | **예지보전 별도 작은 영역**: 주의·위험 설비 이름 + %, 깜빡이지 않음, 누르면 SCR-004 (D-97). 배치도 테두리는 유지 |

**줄이는 것**: 알림 열(세로 열 전체 → 작은 영역), OEE 3요소 막대, 품질 원형/막대의 크기.
**계층**: 배치도 안에서 라인 줄이 단위. 라인 줄 끝 "라인 실적/계획"을 같은 모양으로 6줄 + 도장 줄 (같은 수준은 같은 모양).

### 1.2 SCR-010 라인 상세

**목적 한 줄 [제안]**: 이 라인의 어느 공정이 막혔고, 그 때문에 라인 계획에서 얼마나 뒤처졌는지 본다.

**주인공 [제안]**: 라인 흐름 (슬리팅 → 프레스 1~4단 → 용접). 멈춘 설비와 **공정 사이 재공**(앞에 쌓이고 뒤가 비는 곳 = 막힌 곳)이 한눈에.

| 판단 질문 | 지금 표현 | 문제 | 바꿀 표현 [제안] |
|---|---|---|---|
| 어디서 막혔나 | 설비 칸 + 공정 사이 재공·생산·불량 숫자 | 숫자가 같은 크기로 늘어서 막힌 곳이 안 튐 | 재공이 쌓인 곳·빈 곳을 칸 크기 차이 없이 숫자 굵기·위치로 강조. 고장 칸 깜빡임 + 조치 요청 |
| 라인 계획대로 가나 | 요약 4칸 중 실적/계획/달성률 + 계획선 vs 누적 실적 | 001과 같은 달성률 문제 | 001과 같은 "지금 기준 N개 앞섬/뒤처짐" |
| 라인이 성능을 내나 | 요약 칸 라인 OEE | 기준 없음 | Q-33 |
| 이 라인에 무슨 일이 있었나 | 오늘 알림 목록 | - | 유지, 크기 줄임 |

**계층**: 공정 묶음(이름) > 설비 칸. 공정 이름을 누르면 공정 상세, 설비 칸을 누르면 그 설비 (화면정의서 이벤트 그대로).

### 1.3 SCR-002-3 프레스 상세

**목적 한 줄 [제안]**: 이 프레스 설비가 왜 멈췄는지(또는 멈출 것 같은지) 원인을 찾는다.

**주인공 [제안]**: 선택한 설비의 관리값 그래프. 상·하한을 넘은 지점과 현재 상태 사유("압력(좌) 상한 초과 356/350")가 같이 보이게.

| 판단 질문 | 지금 표현 | 문제 | 바꿀 표현 [제안] |
|---|---|---|---|
| 4단 중 어느 단이 문제인가 | 설비 카드 4개 가로 (단 사이 화살표) | - | 유지. 고장 카드 깜빡임 + 조치 요청 |
| 무엇이 기준을 넘었나 | 관리값 그래프 + 상·하한 점선 | 그래프가 여러 칸 중 하나라 주인공이 아님 | 가장 큰 칸. 사유 문구를 그래프 제목 자리에 |
| 얼마나 자주 멈췄나 | 비가동 이력 목록 + 조치 메모 | - | 유지 |
| 어느 단이 느린가 | 단별 사이클 4칸 (가장 느린 단 강조) | - | 유지 |
| 이 공정에서 불량이 나나 | 공정 검사 숫자 + 불량 목록 | - | 유지, 아래쪽 |

## 2. 나머지 화면 — 목적 한 줄과 주인공 [제안]

화면정의서의 목적 문장을 "사용자가 무엇을 판단하나"로 다시 적었다. 시안 대상은 아니지만 구현 단계(11단계)에서 같은 방식으로 다시 짠다.

| 화면 | 목적 한 줄 | 주인공 |
|---|---|---|
| SCR-002-1 코일입고 | 슬리팅 앞 재고가 모자라지 않은지 본다 | 슬리팅 앞 재고 추이 |
| SCR-002-2 슬리팅 | 슬리터가 왜 멈췄나, 속도가 떨어지는 구간(미세정지 후보)이 있나 | 관리값·속도 그래프 |
| SCR-002-4 용접 | 용접 로봇이 왜 멈췄나 | 관리값 그래프 |
| SCR-002-5 도장 | 도장 설비가 왜 멈췄나, 도장 조건이 기준 안인가 | 관리값 그래프 |
| SCR-002-6 출고 | 비전 검사가 돌고 있나, 출고 불량이 늘고 있나 | 비전 상태 + 출고 불량 |
| SCR-003 가동률 | 라인별 가동률을 비교하며 언제·어디서 멈췄나 돌아본다 (D-108, D-113에서 고침. 처음 정의는 "무엇 때문에 손실이 났나") | 라인별 상태 줄 (OEE·공장 대비·손실 · 24시간 띠). 비가동 코드별 손실은 왼쪽 보조 열 |
| SCR-004 예지보전 | 고장 전에 손봐야 할 설비가 어디인가 | 위험도 목록 |
| SCR-005 3D 공장 | (Q-28 인터뷰 후) | - |
| SCR-006 알람·비가동 이력 | 언제·어디서·왜·얼마나 멈췄나 찾기 | 필터 + 표 |
| SCR-007 리포트 | 하루 결과 확인, 고장 시 재배정안 확인 | 재배정 보고서 |
| SCR-011 생산 조회 | 기간·라인별 계획 대비 생산, 제품 하나의 이력 | 계획 대비 막대 |
| SCR-008·009 설정 | 목표·기준값을 바르게 입력 | 입력 표 |
| SCR-000 로그인 | 로그인 | 입력 칸 |

## 3. 값 표현 점검 (피드백 6)

"이 값을 보고 무엇을 판단하는가"에 답하지 못하는 표현을 찾았다.

| 값 | 판단 | 지금 | 판단을 막는 것 | 제안 |
|---|---|---|---|---|
| 오늘 생산 달성률 | 목표대로 가나 | 실적 ÷ 하루 목표 | 하루 중간에는 항상 낮음 | 지금 기준 차이(N개)를 핵심, 달성률은 보조. 목표선은 지금도 0→목표 직선(`useTodayProduction`)이라 지금 값 계산 가능 [제안] |
| 오늘 생산 그래프 | 언제 빠졌나 | 누적선 vs 목표선 | 누적선은 기울기 변화로만 빠진 시간을 보여 줘 읽기 어려움 | 시간당 막대 추가 (D-98) |
| OEE | 설비 성능이 괜찮은가 | 큰 숫자 + 3요소 | 기준·목표 없음 | Q-33 |
| 출고 불량률 | 품질이 괜찮은가 | 큰 숫자 | 기준 없음 | Q-33 |
| 라인 실적/계획 | 라인이 뒤처졌나 | 숫자 / 숫자 | 하루 계획 대비라 달성률 문제와 같음 | 지금 기준 차이 [제안] |

## 4. 확인한 것 (D-101)

| ID | 질문 | 답 |
|---|---|---|
| ~~Q-33~~ | OEE·불량률을 "괜찮은가"로 읽을 기준이 명세에 없다 | **기준값을 새로 만들지 않고 크기만 낮춘다** (기능 유지). 어제 대비·목표 입력 추가는 하지 않음 |
| ~~Q-34~~ | 대시보드 핵심 숫자 | **"목표보다 N개 앞섬/뒤처짐"**(목표선의 지금 값 − 실적). 달성률·목표는 보조. 라인 상세도 같게 |
| ~~Q-35~~ | 대시보드 예지보전 영역 | **80% 이상 설비의 이름 · % · 주의/위험**, 깜빡임 없음, 누르면 SCR-004 |

"지금 기준 차이"는 기존 값(하루 목표, 지금 시각, 실적)으로 계산하는 표시 방식이라 새 데이터가 필요 없다. 목표선은 지금 00시 0 → 24시 목표의 직선(`useTodayProduction`)이므로 지금 값 = 목표 × 경과 시간 ÷ 24.

## 6. 글자 단계 초안 (06 문서 7장 4단계, 피드백 1)

지금 5단계(13·14·20·32·44)는 개수는 맞지만, 44px이 화면마다 여러 번 쓰여 "크기는 큰데 가독성은 낮은" 원인이 된다. 단계 수는 그대로 두고 **쓰임을 다시 나눈다** [제안].

| 단계 | 크기 / 굵기 | 쓰는 곳 | 지금과 다른 점 |
|---|---|---|---|
| 보조 | 13 / 400 | 축 라벨, 메타, 숫자 위 이름표, 표 머리줄 | 같음 |
| 본문 | 14 / 400 | 표·목록·설명, 설비 칸 글자 | 같음. 강조는 굵기 대신 색(먹/보조 먹)으로 |
| 제목 | 16 / 600 | 패널 제목, 이동 경로 현재 위치 | 패널 제목 14 → 16, 화면 제목 20 → 16 (제목은 하나의 크기) |
| 보통 숫자 | 20 / 600 | 요약 숫자, 상태별 대수, OEE·불량률 | 32 → 20 (주인공이 아닌 숫자는 모두 여기) |
| 핵심 숫자 | 32 / 600 | **화면마다 하나**: 001·010 = "N개 뒤처짐", 002-x = 선택 설비 지속시간 또는 이탈값 | 44 없앰. 한 화면에 두 번 이상 쓰지 않음 |

- 굵기는 400·600 두 가지만 (+ 상태 코드 글자 700). 600은 제목·숫자에만.
- 1차 배치안 3개는 모두 이 단계로 만든다 (D-99: 배치만 다르게).
