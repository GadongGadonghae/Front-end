# 계획수정 보고서 슬랙 전송 — N-01

| 일자 | 내용 |
|---|---|
| 2026-11-20 | 첫 작성. 백엔드 `feat/slack-notify` · 프론트 `feat/vue-base` 구현 기준 (D-120) |

> **이 문서의 용도**: 계획수정 보고서 화면의 [슬랙 전송] 버튼이 무엇을 보내는지, 어디에 구현돼 있는지, 실행하는 PC에서 무엇을 설정해야 하는지를 한곳에 모은 것.
> **누가 읽나**: 화면을 고치는 프론트 담당, 백엔드를 실행하는 담당(설정은 4장).

---

## 1. 무엇을 하나

계획수정 보고서 화면(SCR-007, `/reports/replan/:id`)에서 **[슬랙 전송]** 을 누르면 슬랙 채널에 메시지 1건이 간다.

| 메시지에 들어가는 것 | 내용 |
|---|---|
| 제목 | `🚨 {설비 이름} 고장 · 계획수정 보고서` |
| 고장 장비 | 설비 이름·ID, 라인·공정, 비가동 사유·상세, 발생 시각, 상태(정지 중 N분째 / 해제 시각·지속) |
| 요약 | 보고서를 LLM으로 3줄 요약. 1줄 무엇이 왜 멈췄나 · 2줄 재배정 핵심 · 3줄 목표 영향 |
| 보고서 | 문서번호, 작성자·작성 시각, 승인 상태(승인 / 검토 대기), 부족 수량, 재배정 후 목표 미달, 계산 기준, 라인별 재배정 표, 조치, 위험 |
| 보고서 보기 버튼 | 이 화면으로 바로 여는 링크 (`slack.app-base-url`을 설정한 경우만) |
| 바닥글 | 보낸 사람(로그인 사용자), 요약에 쓴 모델 |

- **보낸 기록은 저장하지 않는다.** 같은 보고서를 다시 누르면 또 간다.
- 고장이 났을 때 **자동으로** 가는 알림이 아니다. 자동 외부 알림은 D-110대로 메일만이다. 이 기능은 사람이 보고서를 보고 **직접 공유**하는 버튼이다 (D-120).

## 2. 동작 순서

```
[슬랙 전송] 클릭
  → POST /api/reassignments/{reportId}/slack   (N-01)
      1. 웹훅 설정 확인 (없으면 바로 503: LLM을 기다리기 전에 알려 줌)
      2. 보고서(R-02와 같은 내용) + 고장 장비 정보 조회
      3. LLM 3줄 요약 (ai.report.* 설정 재사용. 키 없음·실패면 템플릿 문장)
      4. 슬랙 Incoming Webhook으로 1건 전송
  ← { sentAt, mock, summary[], summaryModel, summaryFallbackReason }
```

요약에 20초 안팎 걸린다 (Gemini 기준). 그동안 버튼은 "슬랙 전송 중…"으로 막힌다.

## 3. 화면 동작

| 상황 | 화면 문구 (버튼 아래) |
|---|---|
| 성공 | `슬랙 전송 완료 (HH:mm)` |
| 성공, 요약은 템플릿 | `슬랙 전송 완료 (HH:mm) · AI 요약 실패로 템플릿 문장 사용` |
| 서버가 시험 모드(`slack.mock`) | `슬랙 시험 모드 · 실제로 보내지 않음 (HH:mm)` |
| 웹훅 미설정 (503) | `슬랙 웹훅 주소가 설정되지 않았습니다 (slack.webhook-url)` |
| 슬랙이 거절 (502) | `슬랙 전송에 실패했습니다 (404 no_service)` 처럼 슬랙이 준 이유 |
| 연결 실패 (502) | `슬랙에 연결하지 못했습니다 (인터넷 연결을 확인해 주세요)` |

- 버튼은 보고서를 열었을 때만 누를 수 있고, 보고서를 만드는 중이거나 보내는 중이면 막힌다.
- 다른 보고서로 옮기면 문구는 지워진다.
- 데모 데이터 모드(`VITE_DATA_SOURCE` ≠ `api`)에서는 보내지 않고 시험 모드 문구만 나온다.

## 4. 실행하는 PC에서 할 설정 (백엔드)

웹훅 주소는 **비밀값**이다. 주소만 알면 누구나 그 채널에 글을 올릴 수 있으므로 Git에 올리지 않는다.

1. 슬랙에서 앱 만들기 → **Incoming Webhooks** 켜기 → **Add New Webhook** → 받을 채널 선택 → 주소 복사
2. 백엔드 `src/main/resources/application-local.yml` (Git에 안 올라감)에 추가:
   ```yaml
   slack:
     webhook-url: https://hooks.slack.com/services/...
     app-base-url: http://<서버 PC IP>    # "보고서 보기" 버튼 주소. 비우면 버튼 없음
   ```
3. 요약을 LLM으로 하려면 기존 AI 보고서 키(`ai.report.api-key` 또는 환경 변수 `AI_REPORT_API_KEY`)가 있어야 한다. 없으면 템플릿 문장으로 간다.
4. 그 PC가 **인터넷에 연결**돼 있어야 한다 (슬랙·Gemini 모두 외부 서버).

| 설정 | 환경 변수 | 기본값 | 뜻 |
|---|---|---|---|
| `slack.webhook-url` | `SLACK_WEBHOOK_URL` | 없음 | 웹훅 주소. 없으면 503 |
| `slack.app-base-url` | `SLACK_APP_BASE_URL` | 없음 | 브라우저로 프론트에 접속하는 주소. 뒤에 `/reports/replan/{id}`가 붙는다. `localhost`는 쓰지 않는다(누른 사람 PC를 가리킴) |
| `slack.mock` | `SLACK_MOCK` | `false` | `true`면 보내지 않고 메시지 JSON을 로그에만 남긴다. 웹훅 없이 모양만 볼 때 |
| `slack.timeout-seconds` | `SLACK_TIMEOUT_SECONDS` | `10` | 슬랙 호출 제한 시간 |

**보고서 보기 버튼**은 공유기 안 IP라 같은 네트워크에서만 열린다. 휴대폰 슬랙·외부에서는 열리지 않는다. 로그인 전이면 로그인 화면을 거쳐 그 보고서로 돌아온다.

## 6. 알아 둘 것

- 메시지에 들어가는 사용자 문장(고장 상세·AI 문장)의 `<`, `>`, `&`는 바꿔서 보낸다. `<!channel>` 같은 글이 채널 전체 알림으로 동작하지 않게 하기 위해서다.
- 슬랙 블록 글자 수 제한(본문 3,000자) 때문에 긴 조치·위험은 5개까지만 싣고 "외 N건"으로 줄인다. 보고서 전체는 [보고서 보기]로 본다.
- 실제 슬랙으로 보내 보는 확인은 웹훅이 있는 PC에서 해야 한다. 2026-11-20 작성 시점에는 테스트(웹훅 호출을 가로채 메시지 내용 확인)까지만 했다.
